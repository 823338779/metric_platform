# 双工作台 2.0 实施计划

> 执行方式：使用 superpowers:executing-plans 在当前工作区完成；用户已将方案选择与设计取舍交由助手。

**目标：** 为数据开发与分析人员统一环境、构建、部署、资源和查询体验。

**架构：** 保留 React、Ant Design、现有路由与 API。重组页面布局和信息层级，不引入依赖，不修改后端。公共外壳和主题统一管理，页面特有布局留在对应页面。

**设计依据：** 本计划中的设计约定、PRODUCT.md 的双工作台定位及当前业务实现。

## 设计约定

- 采用双工作台 2.0：全局环境与部署入口；固定构建内资源和分析等权。相较环境中心，分析用户无需重复穿过配置流程。
- 白色工作面、浅灰底、墨色文字、蓝色主操作；导航采用带文字的可收起侧栏。保持业务状态文字，颜色只辅助辨识。
- 环境列表用对齐的记录呈现物理目标；表单按信息用途分组；环境详情以构建历史为主体，配置按需展开。
- 资源继续使用可调整树、阅读区和可收起版本上下文，压缩重复标题、突出定义及分析入口。
- 查询保留直接选择指标和维度；筛选与排序默认展开并允许收起，运行操作靠近条件，结果变化状态明确。版本详情按需展开，异常原因始终可见。普通数据分析不要求先理解 UUID。
- 登录采用简洁品牌介绍与独立表单区；不填充虚构统计或业务结果。

## 全局约束

- 只在 metric-platform 修改，不创建或切换 worktree。
- 保留 buildId、资源 ID、optionId、同步查询及数值精度语义。
- 保留已有测试，新增行为使用最小回归测试；纯视觉调整通过浏览器验收。
- 不改变身份认证，不添加指标 CRUD、导出或仪表盘功能。
- 长名称、失败与空状态、窄屏及键盘焦点必须可用。
- 依照工作区规则，整份计划完成后在产品仓库创建一个提交，不更新根仓库 Git 链接。

## 任务与验证

- [x] 公共外壳、主题、登录：修改 PlatformLayout.tsx、global.css、main.tsx、LoginPage.tsx；添加导航收起回归用例，验证会话退出及固定版本导航。
- [x] 环境及部署：修改 features/environments 页面与表单、PublishedProjectsPage.tsx；保留日志的构建内反馈，避免破坏现有测试与排障上下文；运行 Environments、BuildSubmissionForm、DeploymentVersions 用例。
- [x] 资源及分析：修改资源标题和布局、PublishedWorkbench.tsx、相关 CSS；添加条件变化后的结果状态回归用例；运行目录、查询、结果相关测试。
- [x] 整体验证：前端单测、生产构建，使用协议测试数据验证登录、环境、部署、目录和查询的桌面及窄屏显示；真实服务未验证时明确说明。
- [x] 独立审查、修复、更新 DESIGN.md 和设计 token；检查根与产品 Git 状态，仅提交本任务文件。

## 审查重点

1. 折叠导航后链接及登出仍可通过键盘访问。
2. 长仓库地址、UUID、资源名称不撑破窄屏。
3. 环境保存与构建重试仍携带原版本及幂等身份。
4. 查询执行期间修改条件不能让旧结果被标记为新条件的结果。
5. 目录跳转和版本刷新保留明确的固定构建语义。

## 验证结果

- 前端 29 个测试文件、159 个用例通过；新增导航收起、异步查询条件变化和折叠区外错误提示回归测试，均确认先失败再修复通过。
- TypeScript 检查与 Vite 生产打包通过。本次修改的前端文件均通过 Prettier 检查，`git diff --check` 通过。
- 标准 `npm run build` 被 71 个未修改文件的既有格式问题拦截；抽查确认存在 CRLF 与 LF 的差异，未扩大格式化范围。Vite 仍有大包提示。
- 使用协议测试数据检查 7 类页面的桌面和手机显示，均无页面级横向溢出；验证查询、SQL 展示、结果过期状态及身份读取失败提示。真实服务联调不在本次验证范围内。
- 独立审查发现身份读取失败提示被折叠隐藏，修复后补充桌面和手机截图确认；最终结论为可交付。
