# 数据集字段选择修复设计

## 目标

修复新建数据集从“基本信息”进入“字段配置”后字段控件被禁用的问题，并让用户可以从同一物理表或视图中选择多个不同字段、搜索字段、逐个添加或移除字段。

## 根因

`DatasetEditorPage` 使用 `Form.useWatch` 读取 `dataSourceId` 和 `sourceObjectKey`。向导进入第二步后，第一步的表单项被卸载；默认监听只跟踪已注册字段，因此两个监听值变为 `undefined`。字段加载副作用随即清空字段列表，字段控件也因没有 `sourceObjectKey` 而禁用。

## 方案比较

1. 保留多选下拉框，仅修复跨步骤状态。改动最小，但字段较多时不便浏览，也不够直观地表达增删。
2. 使用可搜索、可勾选的字段列表。用户勾选即添加、取消勾选即移除，并显示已选数量。交互清晰，适合多字段场景，采用此方案。
3. 使用逐行“添加字段”编辑器。扩展性强，但当前只选择字段名称，不需要每行额外配置，复杂度没有收益。

## 设计

- 让数据源和物理对象的表单监听在步骤切换、字段暂时卸载后仍读取保留值，保证字段元数据请求能正常发出。
- 字段配置页展示带复选框的字段列表，每项包含物理字段名和类型。
- 提供本地字段搜索；搜索仅影响展示，不改变已选状态。
- 支持全选当前筛选结果和清空选择，显示“已选择 N 个字段”。
- 已选字段继续写入现有 `selectedPhysicalFields: string[]`，不改变后端请求结构或 API 契约。
- 切换数据源或物理对象时清空旧选择，避免把其他表的字段提交给当前表。

## 错误与空状态

- 字段加载时显示加载状态。
- 字段接口失败时保留现有错误提示并展示空列表。
- 物理对象没有字段时展示明确空状态。
- 未选择任何字段时不允许进入下一步，并沿用“请至少选择一个字段”的校验语义。

## 验证

- 无落盘浏览器复现：选择数据源和表后进入第二步，字段请求发生且列表可用。
- 验证选择多个字段、取消单个字段、搜索、全选筛选结果、清空选择。
- 验证提交体中的 `selectedPhysicalFields` 与最终勾选字段完全一致。
- 运行现有前端测试及生产构建。项目规则禁止未经用户明确要求修改测试代码，因此不新增或改动测试文件。

## 大字段量与响应式布局修订

### 问题审查

- 创建态 `PhysicalFieldSelector` 关闭了分页但没有纵向滚动上限，字段数量会直接撑高页面。
- 编辑态 `FieldTable` 使用相同的无限增长方式，存在同类问题。
- 字段搜索框使用固定宽度，窄屏下工具栏可能溢出。
- 字段名、显示名或类型较长时，表格没有横向滚动保护。
- 预览步骤的 JSON 使用普通 `pre`，长内容可能撑宽页面；读取值时也应包含已卸载步骤保留的表单字段。
- 主内容布局缺少 `minWidth: 0`，Flex 子项在长内容场景下可能把整体页面横向撑开。
- 应用没有全局页面重置，浏览器默认的 `body { margin: 8px }` 会让 `100vh` 根布局固定超出视口 16 像素。

### 选定方案

创建态与编辑态字段表均保持无分页，但将表体最大高度固定为约 400 像素，超出后在表格内部滚动，并固定表头。相比分页，这种方式能连续浏览和批量勾选字段，同时不会改变向导整体高度。

### 布局规则

- 两个字段表统一设置纵向滚动上限、固定表头和横向滚动下限。
- 搜索与“已选择/清空选择”工具栏允许换行，搜索框最大宽度 320 像素、窄屏时缩至容器宽度。
- 向导内容容器设置 `minWidth: 0`，底部“上一步/下一步”紧随有界内容区域，不再被字段数推到远处。
- 预览 JSON 同时限制纵向高度和横向宽度，在区域内部滚动，并从完整保留表单状态读取数据。
- 平台主内容 Flex 子项设置 `minWidth: 0`，避免任何长表格或长文本撑宽整页。
- 全局将 `body` 外边距重置为 0，并保证 `html`、`body`、`#root` 具备完整最小高度，使根布局与视口精确对齐。

### 额外验证

- 使用至少 100 个字段验证页面高度保持稳定、表头固定、滚动只发生在表体内。
- 在 1440×900 与 768×900 两种视口验证无整页横向溢出，搜索工具栏能够换行。
- 验证创建态勾选、搜索、清空和编辑态字段开关在内部滚动后仍可操作。
