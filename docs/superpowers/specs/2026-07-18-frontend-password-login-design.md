# Metric Platform 前端账号密码登录设计

## 目标

为 Metric Platform 创建一个本地平台管理员账号，并将前端从固定 `admin-token` 改为账号密码登录。所有受保护页面必须要求有效登录；任意业务接口发现令牌失效时，统一跳转登录页，重新登录后返回失效前页面。

## 范围

- 使用后端现有账号密码令牌接口，不引入新的认证协议。
- 登录页和登录请求都只包含账号和密码。
- 用户名在整个平台范围内唯一；租户、角色、权限和工作区均为账号及其关联数据的属性。
- 登录状态保存在浏览器 `sessionStorage`，刷新当前标签页后仍然有效，关闭标签页后清除。
- 后端访问令牌有效期固定为 10 小时。
- 创建一个用户名为 `admin`、角色为 `PLATFORM_ADMIN` 的本地管理员账号。
- 管理员初始密码随机生成，不将明文写入仓库。
- 不扩展注册、找回密码、自动续期、多租户选择或记住登录功能。

## 管理员账号创建

使用现有 `PlatformIdentityBootstrap` 一次性创建账号，避免绕过后端密码编码和审计逻辑。

- 租户：`default`
- 用户名：`admin`
- 显示名称：`Platform Administrator`
- 角色：`PLATFORM_ADMIN`
- 密码：执行时生成的随机强密码

启动时临时提供 bootstrap 环境变量。账号成功写入数据库后，不把密码或 bootstrap 配置提交到仓库。最终通过登录接口验证账号可用，并把初始密码交付给用户。

## 后端令牌配置

将 Metric Platform 的访问令牌有效期从 10 分钟调整为固定 10 小时：

- `metric-platform.identity-auth.token-ttl` 使用 `PT10H`。
- `PlatformIdentityProperties` 的配置校验要求有效期恰好等于 10 小时。
- 登录响应的 `expiresIn` 由现有服务按配置计算，预期为 `36000` 秒。
- 令牌仍保存在 `platform_access_token`，继续执行撤销、账号状态和 `authVersion` 校验。
- 令牌记录的 audience 继续由后端固定为 `data-agent`，但不再接受客户端传入。

## 后端账号查找与唯一性

新增 Flyway 迁移，将 `platform_user` 的 `(tenant_id, username)` 联合唯一约束替换为全平台 `username` 唯一约束。迁移前规范化现有用户名并让重复值导致迁移失败，避免静默合并不同账号。

登录服务按规范化后的全局用户名查找账号，再通过账号的 `tenantId` 加载并校验租户。账号状态、租户状态、锁定状态、密码、角色、权限和工作区继续在后端校验或派生。登录限流键改为来源地址与用户名，不再依赖客户端提供的租户。

管理员创建账号和 bootstrap 仍为账号指定租户，但数据库唯一约束保证任何租户都不能创建重复用户名。冲突响应使用全平台用户名已存在的语义。

## 前端架构

### 认证状态模块

新增一个小型认证状态模块，集中负责：

- 从 `sessionStorage` 读取访问令牌和身份摘要。
- 保存登录成功返回的令牌和身份摘要。
- 清除登录状态。
- 保存并校验登录后返回地址，只允许站内路径。

业务代码不直接访问固定 token，也不自行拼接认证状态。

### 认证 API

登录请求发送到 `POST /api/v1/auth/token`：

```json
{
  "username": "<用户输入>",
  "password": "<用户输入>"
}
```

应用恢复登录状态时，使用保存的 Bearer Token 请求 `GET /api/v1/auth/me`。登录接口和身份校验接口与普通业务 API 共用相同的 API 根路径配置。

### HTTP 客户端

现有 HTTP 客户端在每次请求发出前动态读取 `sessionStorage` 中的 Token，不再使用构建时常量或 `admin-token` 回退值。

普通业务请求收到 401 时：

1. 清除认证状态。
2. 记录当前 pathname、search 和 hash。
3. 导航至 `/login`，并标记“登录已过期”。
4. 多个并发 401 只执行一次跳转。

登录请求自己的 401 不触发全局跳转，只在表单内显示账号或密码错误。403 保持为权限不足，不清除登录状态。

### 路由守卫

- `/login` 为公开路由。
- 其余现有路由均置于认证守卫下。
- 应用首次加载且 `sessionStorage` 没有 Token 时，直接进入登录页。
- 存在 Token 时先调用 `/auth/me`；校验成功后渲染平台布局，失败则清理状态并进入登录页。
- 登录成功后返回先前保存的站内地址；没有返回地址时进入数据源首页。

### 登录页面

登录页沿用现有 Ant Design 主题，使用居中的登录卡片，包含：

- Metric Platform 标识与简短说明。
- 账号输入框。
- 密码输入框。
- 登录按钮和提交中的加载状态。
- 凭据错误、网络错误和登录过期提示。

提交时禁止重复请求。账号和密码仅做必填校验，不在浏览器保存密码。

## 安全边界

- 不把管理员明文密码、访问令牌或密码哈希写入仓库。
- 不使用 URL 参数传递令牌。
- 不接受客户端指定租户、角色、权限、工作区或令牌 audience。
- 返回地址必须是以 `/` 开头的站内路径，拒绝协议地址和双斜杠地址，避免开放重定向。
- `sessionStorage` 只降低跨浏览器会话持久化风险，不能替代前端 XSS 防护。
- 服务端继续作为令牌有效性的最终判断来源；前端不根据本地时间自行延长令牌。

## 验证

遵守工作区规则，不新增、删除或修改测试代码。使用以下现有检查和人工验证：

1. 运行前端格式检查、TypeScript 构建和 Vite 生产构建。
2. 启动后端并通过 `/api/v1/auth/token` 验证管理员登录成功，确认 `expiresIn` 为 `36000`。
3. 使用返回 Token 调用 `/api/v1/auth/me` 和受保护业务接口。
4. 在浏览器验证未登录访问受保护页面会进入登录页。
5. 验证正确账号密码登录后进入原目标页面，刷新后保持登录。
6. 使用无效或过期 Token 触发业务接口 401，确认跳转登录页并显示过期提示。
7. 重新登录后确认返回过期前页面。
8. 验证错误密码只显示表单错误，不产生跳转循环。
9. 验证跨租户创建同名账号会返回冲突，且登录获得的租户与权限来自账号记录。

## 非目标

- 自动刷新或滑动续期 Token。
- 跨标签页同步登录状态。
- 用户自助注册、修改密码或找回密码。
- 账号管理页面或多租户选择器。
- 调整现有角色、数据集授权或多租户隔离模型。
