# 查询拖拽构建器设计

## 目标

将查询工作台现有的两个多选下拉框替换为拖拽式查询构建器。用户从左侧语义对象库选择可用指标和维度，拖到右侧对应投放区，并可调整顺序或移除对象。

## 选定布局

采用“对象库 + 查询画布”双栏布局：

- 左栏是统一的可用语义对象库，包含搜索框和指标/维度类型标识。
- 右栏垂直排列“指标”和“维度”两个投放区。
- 桌面端保持双栏；窄屏下对象库与查询画布改为上下排列。

未采用三列看板，因为中小屏幕空间不足，且指标、维度投放区不需要与对象库保持等宽。

## 交互规则

- 页面进入时加载全部可用指标与维度；输入搜索词时更新左侧对象库。
- 指标只能放入指标区，维度只能放入维度区。拖到错误区域时不改变选择，并显示明确提示。
- 同一个对象在同一区域只能出现一次；已经选择的对象在左侧显示已添加状态。
- 投放区内部支持拖拽排序。排序决定请求中 `metricIds` 和 `dimensions` 的顺序。
- 每个已选对象提供明确的移除按钮。
- 指标区至少包含一个对象才会触发查询校验并允许执行；维度区可以为空。
- 搜索不会清空或隐藏右侧已经选择的对象。

## 可访问与触屏替代

原生拖拽不是可靠的键盘和触屏交互，因此每个左侧对象同时提供“添加”操作，已选对象提供“上移”“下移”和“移除”操作。所有操作使用原生按钮和可读标签，拖拽只是主要的鼠标交互方式，不是唯一方式。

## 组件边界

- `SemanticObjectPicker` 改为拖拽构建器外壳，负责搜索、加载状态、对象库与两个投放区布局。
- 提取纯函数处理去重添加、移除和重排，输入输出均为字符串 ID 数组，继续调用现有 `onMetrics` 和 `onDimensions`。
- `QueryWorkbenchPage` 保持现有查询请求、校验和执行逻辑，不改变 API 请求结构。
- 不引入新的拖拽依赖；使用浏览器原生 Drag and Drop API，控制本次改动范围。

## 状态与错误

- 搜索加载时显示加载状态；没有匹配项时展示空状态。
- 搜索失败时保留当前已选项，并在对象库区域显示错误，不产生未处理 Promise。
- 通过请求序号忽略过期搜索响应，避免快速输入时旧响应覆盖新结果。
- 拖拽过程中仅高亮类型兼容的投放区。

## 视觉规则

- 构建器填满卡片可用宽度，左栏约占 40%，右栏约占 60%。
- 对象库与投放区设置合理最大高度并内部滚动，不能撑高整个页面。
- 指标与维度使用稳定但克制的类型标识；对象名称始终完整可读或提供省略提示。
- 空投放区显示具体动作提示，不使用只有图标的空白框。

## 验证

- 浏览器验证从对象库拖入指标、拖入维度、错误类型投放、重复投放、排序和移除。
- 验证点击添加、上移、下移、移除的替代操作。
- 验证搜索、空状态、失败状态和过期响应保护。
- 验证 100 个语义对象时只在构建器内部滚动，页面不出现横向或额外纵向溢出。
- 在 1440×900、768×900 和触屏模拟环境验证布局与操作。
- 验证最终 `QueryRequest` 继续使用 `metricIds`、`dimensions` 和 `relationshipIds`，不修改后端契约。
- 运行现有前端测试和生产构建；项目规则禁止未经用户明确要求修改测试文件，因此不新增或改动测试代码。
