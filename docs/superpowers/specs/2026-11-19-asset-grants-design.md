# 已部署资产归属与逐项授权

## 资产身份

平台按租户、执行环境和资产类型隔离授权，仓库和分支取自当前生效构建。各类授权键按原生名称精确匹配。

| 资产 | 稳定标识 |
| --- | --- |
| 指标 | 指标节点的 `name` |
| 数据集 | 可预览的 dbt model 节点的 `name` |
| 维度 | 所属 semantic_model 的 `name` 与维度原生 `name` 的组合 |

使用当前构建登记的节点标识和选择器执行查询。单用短名称会混淆不同模型中的同名维度，按构建 ID 授权则会在每次部署后失效。查询使用的指标名、维度选项和预览选择器均须在请求指定的构建中唯一解析。显示名、构建 ID 及随指标集合变化的 `optionId` 均不参与长期授权键。

## 登记和管理

以服务确认的实际生效构建为准，完整读取对应目录，再以事务登记资产与该租户唯一管理者的账号身份。保存授权所需的标识和构建关联，业务定义与发布状态继续由 dbt-service 管理。登记可重复执行；目录读取失败可重试，部分结果不得成为可授权目录。现有生效部署也经同一登记流程补齐。

重新部署同一标识保留授权，显示名变化不影响授权。原生名称变化按新资产处理。普通用户仅能访问目标当前生效且已完整登记的构建，旧构建按版本失效提示刷新。资产移除后授权休眠，同一环境恢复相同标识时恢复仍有效的授权。同名资源处于不同租户或执行环境时独立授权。

管理者在控制台选择本租户用户，按资产分别授予或撤销使用权。后端校验操作者、用户和资产的租户归属。资产列表返回本租户当前已部署的全部资产，按登录账号关联所有者和授权记录计算每项的 `granted`。页面为未授权项显示“无权限”，仅对已授权项开放查询或预览。部署、授权管理和读取项目源码仍按管理者权限校验。

## 查询执行

平台后端在向 dbt-service 提交执行或编译请求前，先校验租户、请求构建和全部显式引用。指标汇总逐项校验指标；分组、过滤、排序和维度值查询校验其中引用的每个指标和维度。指标内部计算依赖无需另行授权。数据集明细预览单独校验数据集。可选维度清单只展示用户有权使用的选项。

一个资源缺少授权就拒绝整条查询，返回 HTTP 403 和用户可读的无权限提示。控制台展示该提示。直接调用 API 与控制台适用相同规则。缺少必要名称字段或无法唯一解析的选项从普通用户清单隐藏，直接引用也不得执行。

## 验收

- 同一资产连续部署两次，已有授权仍有效；新增资产默认仅管理者可用。
- 同名维度属于不同语义模型时分别授权；不同租户或环境的授权相互隔离；同一环境切换仓库或分支后，仍按名称恢复授权。
- 仅授予一个指标即可查询其汇总值；混入未授权指标，或在分组、过滤、排序中引用未授权维度时，整条请求返回 403，执行服务未收到查询。
- 维度值、查询编译和数据集预览各自执行同样的权限检查。撤销后下次请求立即生效。
- 按变更更新 OpenAPI、后端回归测试和控制台交互测试。
