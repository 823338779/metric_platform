# 已部署资产归属与逐项授权

## 资产身份

部署目标沿用 dbt-service 公开契约中的仓库、环境和分支，平台再按租户隔离。目标内的授权键如下，各组成字段按原值精确匹配。

| 资产 | 稳定标识 |
| --- | --- |
| 指标 | 指标节点的 dbt `unique_id` |
| 数据集 | 可预览的 dbt model 节点的 `unique_id` |
| 维度 | 所属 semantic_model 的 `unique_id` 与维度原生 `name` 的组合 |

采用目录已有的限定标识。单用短名称会混淆不同模型中的同名维度，按构建 ID 授权则会在每次部署后失效。查询使用的指标名、维度选项和预览选择器均须在请求指定的构建中唯一解析。显示名、构建 ID 及随指标集合变化的 `optionId` 均不参与长期授权键。

## 登记和管理

以服务确认的实际生效构建为准，完整读取对应目录，再以事务登记资产与该租户唯一管理者的账号身份。保存授权所需的标识和构建关联，业务定义与发布状态继续由 dbt-service 管理。登记可重复执行；目录读取失败可重试，部分结果不得成为可授权目录。现有生效部署也经同一登记流程补齐。

重新部署同一标识保留授权，显示名变化不影响授权。原生标识变化按新资产处理。普通用户仅能访问目标当前生效且已完整登记的构建，旧构建按版本失效提示刷新。资产移除后授权休眠，同目标恢复相同标识时恢复仍有效的授权。同名资源处于不同租户或部署目标时独立授权。

管理者在控制台选择本租户用户，按资产分别授予或撤销使用权。后端校验操作者、用户和资产的租户归属。普通用户仅能浏览和使用获授权的资产；资产使用权不包含部署、授权管理或读取项目源码的权限。

## 查询执行

平台后端在向 dbt-service 提交执行或编译请求前，先校验租户、请求构建和全部显式引用。指标汇总逐项校验指标；分组、过滤、排序和维度值查询校验其中引用的每个指标和维度。指标内部计算依赖无需另行授权。数据集明细预览单独校验数据集。可选维度清单只展示用户有权使用的选项。

一个资源缺少授权就拒绝整条查询，返回 HTTP 403 和用户可读的无权限提示。控制台展示该提示。直接调用 API 与控制台适用相同规则。缺少必要名称字段或无法唯一解析的选项从普通用户清单隐藏，直接引用也不得执行。

## 验收

- 同一资产连续部署两次，已有授权仍有效；新增资产默认仅管理者可用。
- 同名维度属于不同语义模型时分别授权；不同租户、仓库或分支的授权相互隔离。
- 仅授予一个指标即可查询其汇总值；混入未授权指标，或在分组、过滤、排序中引用未授权维度时，整条请求返回 403，执行服务未收到查询。
- 维度值、查询编译和数据集预览各自执行同样的权限检查。撤销后下次请求立即生效。
- 按变更更新 OpenAPI、后端回归测试和控制台交互测试。
